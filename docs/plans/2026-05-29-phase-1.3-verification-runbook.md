### What didn't work — three new findings

| # | Issue | Detail |
|---|---|---|
| 1 | `--bare` is incompatible with OAuth/keychain auth | Per `claude --help`: "Anthropic auth is strictly ANTHROPIC_API_KEY or apiKeyHelper via --settings". The user logs in via `claude login` (OAuth) and has neither an API key nor an `apiKeyHelper` configured. Reverted `--bare` from watchdog + worker spawn in commit `5f4fba7`. Phase 1.4 should consider conditional `--bare` (only when `ANTHROPIC_API_KEY` is set or `apiKeyHelper` exists). |
| 2 | T2 timeout bump didn't apply to fresh inits | `applyDefaults` bumped 300→480, but `init.go`'s hardcoded value in `RunInit` was also 300 and overrode the default. Fixed in commit `f512170` — but only for *new* workspaces. Existing workspaces must hand-edit `.hive/config.yaml`. |
| 3 | **Anti-exploration imperatives are ineffective** | Session log analysis (`9fee9c7c-...jsonl`) of the 5-min hang: **0 skill invocations** of `hive-v2-manager`. 10 Bash commands, all exploratory: `ls /Users/jannik/.claude/skills/`, `find /Users/jannik/.claude -iname '*hive*'`, `find / -maxdepth 5 -iname ...`, `ls /private/tmp/hive-verify-ws/...`, etc. **21 plugin-hook invocations** (3 hooks per tool call × 7 tool calls). The MUST/MUST NOT bullets at the top of the skill didn't prevent any of this. |

### What was untested this run

## Issues filed for Phase 1.4

| Priority | Issue | Recommended fix |
|---|---|---|
| **HIGH** | Manager doesn't invoke its skill — spends time exploring instead | **`--system-prompt-file` inlining** (the "C" option from the P1.3 brainstorm). Watchdog reads `<workspace>/.claude/skills/manager.md` content and passes via `--system-prompt-file` (or `--append-system-prompt-file`). Manager is no longer "a model that should invoke a skill" — it IS the manager because its system prompt says so. No skill-discovery cycle, no exploratory orientation possible. |
| **HIGH** | Existing workspaces still have `manager_timeout_seconds: 300` | Add an upgrade command (e.g., `hive upgrade-config`) that patches `.hive/config.yaml` to current defaults. OR document the manual edit. |
| MEDIUM | `--bare` is the right call when API-key auth is available, but breaks OAuth | Conditional in watchdog: if `os.Getenv("ANTHROPIC_API_KEY") != ""` then add `--bare`, else don't. Skill spawn recipe stays without `--bare` (workers inherit watchdog env minus `--bare` flag). |
| MEDIUM | Plugin hook overhead (21 invocations in our test run) | Two paths: (a) `--bare` (gated by HIGH-priority API-key path); (b) Document that users running hive should disable global plugin hooks in their `.claude/settings.json` for hive workspaces. |
| LOW | Bufio scanner doesn't help when claude in `--print` mode buffers entire response until completion | Future option: tee from claude's session JSONL (which IS written line-by-line as the session progresses) for true real-time observability. |

## Conclusion

Phase 1.3's named fixes for `hive status` and the empty-`manager.log` diagnostic landed and work. But the manager-hang root cause turned out to be deeper than the spec anticipated: the model never invokes the workspace-local skill at all — it spends its budget on exploratory filesystem reads. Prose imperatives aren't enough.

**Recommended next phase: Phase 1.4** — switch to `--system-prompt-file` inlining (option C from the P1.3 brainstorm). Re-run this same verification scenario; if the manager still doesn't drive forward when its system prompt IS the manager skill, escalate to a deeper investigation of hook/runtime interactions.

The bufio scanner from P1.3 is the unsung hero of this whole exercise. Without it, every iteration would have been "empty manager.log, no idea what happened." With it, we surfaced the OAuth issue in milliseconds and the exploration problem in a single 5-min run.
