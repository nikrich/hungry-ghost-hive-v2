# Phase 1.4 — `--system-prompt-file` Inlining Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "ask claude to invoke the manager skill" pattern with "make the manager skill *be* claude's system prompt." Same pattern for workers (junior).

**Architecture:** Two file changes — watchdog spawns with `--system-prompt-file <workspace>/.claude/skills/manager.md`; manager skill's worker-spawn Bash recipe spawns with `--system-prompt-file $(pwd)/.claude/skills/junior.md`. User prompts shrink to one-line triggers.

**Tech Stack:** Same as Phase 1.3 — Go 1.22+, no new deps. Skill markdown unchanged structurally.

**Spec reference:** [`docs/specs/2026-05-29-phase-1.4-system-prompt-inlining-design.md`](../specs/2026-05-29-phase-1.4-system-prompt-inlining-design.md)

### Step 2.1: Find the worker-spawn Bash block

It currently looks like (around step 2, "Spawn at most one worker"):

### Step 2.2: Replace with the `--system-prompt-file` version

Use Edit to replace exactly the block above with:

```bash
nohup claude --print --permission-mode acceptEdits \
  --system-prompt-file "$(pwd)/.claude/skills/junior.md" \
  "You are agent <id>. Worktree: repos/<team>--junior-<id>. Read .hive/agents/<id>/context.md and begin." \
  > /dev/null 2>&1 &
WORKER_PID=$!
echo $WORKER_PID > .hive/agents/<id>/worker.pid
```

Differences:
- Added `--system-prompt-file "$(pwd)/.claude/skills/junior.md"` on its own line (line-continued with `\`)
- The user prompt dropped "invoke the hive-v2-junior skill" (system prompt IS the skill now); shorter and more focused
- The manager's cwd IS the workspace root, so `$(pwd)` gives the right absolute path for the junior skill file
