## How to run

This runbook isn't auto-executed; it spawns real `claude --print` subprocesses and burns OAuth credits. Run it by hand once you're ready to gate-check Phase 2.D.

### 1. Build the binary

```sh
cd /Users/jannik/development/nikrich/hungry-ghost-hive-v2
go build -o /tmp/hive-v2 ./cmd/hive
/tmp/hive-v2 --help   # confirm `merge` subcommand is registered
```

### 2. Create workspace + bare remote

```sh
rm -rf /tmp/hive-verify-ws /tmp/hive-verify-bare /tmp/hive-verify-target
mkdir -p /tmp/hive-verify-ws

git init --bare /tmp/hive-verify-bare
git init -b main /tmp/hive-verify-target
cd /tmp/hive-verify-target
git config user.email test@example.com
git config user.name test
cat > go.mod <<'EOF'
module example.com/api

go 1.22
EOF
mkdir -p api
cat > api/version.go <<'EOF'
package api

const Version = "v1.0.0"
EOF
git add .
git commit -m "seed"
git remote add origin /tmp/hive-verify-bare
git push origin main

cd /tmp/hive-verify-ws
/tmp/hive-v2 init --team api=/tmp/hive-verify-bare
```

### 3. Queue the 3-independent-story requirement

```sh
cd /tmp/hive-verify-ws
/tmp/hive-v2 add-req "Add three doc updates to the test API repo:
1. README.md should get a new ## Quick Start section above the existing content.
2. README.md should get a new ## Endpoints section at the very bottom listing /version.
3. A CHANGELOG.md file should be created (it doesn't exist yet) with a single line: '- initial scaffold'.

Each of these is independent of the others — they touch different files (or distant sections of the same file) and have no shared logic."
```

### 4. Start the watchdog and observe ≥6 ticks

```sh
cd /tmp/hive-verify-ws
/tmp/hive-v2 run --foreground 2>&1 | tee /tmp/hive-verify-watchdog.log
```

In a second terminal:

```sh
# Mid-tick liveness check (between ticks 2 and 4)
ps aux | grep 'claude --print --system-prompt-file' | grep -v grep

# Confirm feature branch landed
git -C /tmp/hive-verify-bare branch -a

# Watch the manager diary live
tail -F /tmp/hive-verify-ws/.hive/log/manager.log | grep tick-end
```

What to watch for, tick by tick:
- **Tick 1:** Drain inbox → spawn `tech-lead`. Diary `spawned=tech-lead`.
- **Tick 2-ish:** Tech-lead exits → requirement is `decomposed`, feature branch exists on bare remote, 3 story drawers exist with the same `feature_branch:` field.
- **Tick 3-ish:** Manager spawns multiple workers in ONE tick. Diary `spawned=junior,junior,junior` (or whatever roles depending on points). `ps aux` shows multiple live `claude --print` PIDs.
- **Tick 4-N:** Workers complete and exit at story `status: review`.

Stop the watchdog with Ctrl-C once all 3 stories sit at `review` and no workers are alive.

### 5. Merge each completed story

```sh
cd /tmp/hive-verify-ws
/tmp/hive-v2 status                              # confirm 3 stories at "review"
/tmp/hive-v2 merge "<title of story 1>"
/tmp/hive-v2 merge "<title of story 2>"
/tmp/hive-v2 merge "<title of story 3>"
```

Each successful call prints `Merged origin/agent/... into origin/feature/...` then `Story "<title>" → merged`.

### 6. Verify the bare remote + drawers

```sh
git -C /tmp/hive-verify-bare log --oneline feature/<slug>
ls /tmp/hive-verify-ws/.hive/memory/wings/hive/rooms/stories/
grep -l 'status: merged' /tmp/hive-verify-ws/.hive/memory/wings/hive/rooms/stories/*.md
```

Expected: feature branch shows 3 merge commits + the seed; all 3 story drawers read `status: merged` with `merged_at:` populated.

### 7. Run one more tick to transition the requirement to `complete`

```sh
cd /tmp/hive-verify-ws
/tmp/hive-v2 run --foreground &
WATCHDOG=$!
sleep 80   # one tick + buffer
kill $WATCHDOG
/tmp/hive-v2 status
```

Expected: 3 stories `merged`; requirement → `complete`.

### 8. Exercise the dry-run + refusal cases

```sh
/tmp/hive-v2 merge --dry-run "<title of story 1>"   # already merged — should refuse
/tmp/hive-v2 merge "<title of story 1>"             # already merged — should refuse with "cannot merge"
```

Expected: both invocations error with `"cannot merge (must be 'review')"`.
