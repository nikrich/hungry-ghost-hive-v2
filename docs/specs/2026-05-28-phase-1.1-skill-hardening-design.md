# Phase 1.1 — Skill Hardening + Init Polish

**Status:** Draft — pending implementation plan
**Date:** 2026-05-28
**Predecessor:** `2026-05-27-architecture-design.md` (Phase 0 spec), `2026-05-27-phase-1-minimal-foundation.md` (Phase 1 plan), `2026-05-27-phase-1-verification-runbook.md` (executed Phase 1 verification)

## 1. Summary

Phase 1's verification revealed three gaps between *designed* behaviour and *actual* behaviour:

1. The manager skill let the model do the work in-session instead of dispatching a worker subprocess
2. The manager skill didn't drive mempalace drawer writes
3. The bundled `mcp.json` template used a placeholder command that doesn't work on most machines

Plus one minor footgun:

4. `hive init` accepted a local non-bare path as a team `repo_url`, which causes `git push` to fail later

Phase 1.1 is a tightly-scoped fix pass for these four items. No new packages, no new CLI commands. A second run of the Phase 1 verification runbook should produce the *full designed flow* — worker subprocess, mempalace drawers, tick completion under ~2 minutes.

## 2. Goals & Non-goals

### Goals

- Re-running `docs/plans/2026-05-27-phase-1-verification-runbook.md` produces:
  - Manager spawns at least one worker subprocess (`.hive/agents/<id>/` exists during the run)
  - Worker runs the junior skill, makes the change, exits cleanly
  - Mempalace wing `hive-<slug>` exists with at least a requirement drawer, a story drawer, and an agent-state drawer
  - Diary log contains at least one `manager  tick-end` event
- `hive init` on a machine with mempalace already configured for Claude Code produces a workspace whose `.claude/mcp.json` works without manual editing
- `hive init` warns when a team `repo_url` is a non-bare local path

### Non-goals

- Permission-based enforcement of manager-must-spawn-workers (deliberately chose prose-only — defer to Phase 1.2 if prose fails again)
- Switching the manager runtime to Sonnet for perf (defer to Phase 4)
- Real-remote PR verification (still requires user-provided test repo + working `gh`)
- Spawning workers in parallel (still Phase 3)
- Re-architecting the workspace-to-machine portability concern (the auto-detect splice writes the user's absolute venv python path into the workspace — fine for Phase 1.1; address in Phase 2 if it becomes a real problem)

## 4. Changes

### 4.1 Rewrite `assets/skills/manager.md`

Same role + responsibilities as Phase 1; sharper language. Specifically:

- **Lead with a one-line MUST/MUST NOT block** at the very top of the body, before any prose. The model reads imperatives at the top as load-bearing.
- **Explicit tool restriction in prose:** "You may NOT use Edit, Write, or MultiEdit. Use Bash to spawn worker subprocesses and the mempalace MCP tools for state. Read is fine for inspecting `.hive/inbox/` and `.hive/agents/`."
- **Numbered steps** with sub-bullets — the model follows numbered procedures more reliably than prose paragraphs.
- **Codify the `inbox/processed/` move pattern** the model improvised in Phase 1 — better than the original "delete" instruction since it preserves a paper trail.
- **"What success looks like" example block** showing the literal sequence of mempalace tool calls expected for a single happy-path tick (drain → add_drawer requirement → add_drawer story → spawn worker via Bash → add_drawer agent-state → diary_write tick-end).
- **"After tick checklist"** — a final block before the constraints section listing the questions the manager should answer before exiting: "Did you add a story drawer? Did you add an agent-state drawer? Did you spawn a worker process? Did you write a diary entry?" Forces self-verification.

The skill stays under 120 lines.

### 4.2 Rewrite `assets/skills/junior.md`

Same treatment, smaller scope (no orchestration logic):

- Lead with MUST/MUST NOT block (You MUST read your context.md first. You MUST commit and push. You MUST update your agent-state and story drawers. You MUST exit.)
- Numbered procedure
- "After completion checklist" — did you update agent-state? did you update story? did you exit?

Phase 1 never actually ran the junior skill (manager shortcut), so this is preemptive — when the junior *does* run in Phase 1.1 verification, the same imperative pattern that Phase 1.1 expects of the manager carries over.

### 4.3 `hive init` auto-detects mempalace MCP

New helpers in `internal/cli/init.go`:

```go
// discoverMempalaceMCP reads ~/.claude.json and returns the user's existing
// mempalace MCP server config as a raw JSON message. Returns os.ErrNotExist
// if ~/.claude.json doesn't exist or doesn't contain an mcpServers.mempalace
// block.
func discoverMempalaceMCP() (json.RawMessage, error)
```

Call site in `RunInit`:

1. After writing the bundled `mcp.json` from assets, attempt `discoverMempalaceMCP()`.
2. If found: rewrite the just-written `.claude/mcp.json` so the `mcpServers.mempalace` block matches the discovered config. Print to stdout: `mempalace MCP: auto-configured from ~/.claude.json`.
3. If `os.ErrNotExist` (or no mempalace block in the json): leave the bundled placeholder, print to stderr: `warning: mempalace MCP config is a placeholder. Edit .claude/mcp.json with your install's command before running hive run`.
4. Other errors: propagate.

The bundled `assets/mcp.json` placeholder is updated to be obviously-a-placeholder rather than a stub that looks valid:

```json
{
  "mcpServers": {
    "mempalace": {
      "command": "<edit-me-or-let-hive-init-auto-detect>",
      "args": ["-m", "mempalace_gateway.server"],
      "env": {
        "MEMPALACE_ROOT": "<path-to-mempalace-data-dir>"
      }
    }
  }
}
```

### 4.4 `hive init` warns on local non-bare team repo

New helper in `internal/cli/init.go`:

```go
// isLocalNonBareRepo returns true if url is a filesystem path AND the
// directory contains a git repo whose core.bare config is "false" or unset.
// Returns false on any other URL shape (http://, ssh://, git@, etc.) and on
// any error (e.g., dir doesn't exist).
func isLocalNonBareRepo(url string) bool
```

Detection: a URL is "a filesystem path" if it starts with `/`, `./`, or `../`, OR if it lacks a scheme + colon. Run `git -C <url> rev-parse --is-bare-repository` (one process spawn per team — fine at small N).

Call site: in `RunInit`'s team loop, after parsing each `--team`, if `isLocalNonBareRepo(team.URL)` then print to stderr: `warning: team <name>'s repo (<url>) is a non-bare local repo. Workers will fail at 'git push' (denyCurrentBranch). Use a bare repo (git init --bare) or a remote URL.`

Init proceeds normally — just warns.

## 8. Open risks

| Risk | Mitigation |
|---|---|
| Prose enforcement still fails | Phase 1.2 with permission split is queued as contingency; we'll know within one verification cycle |
